Specimens

    A field guide

    Web design, one specimen at a time.

    Every entry below is a real, working example of a layout, component, interaction, or visual style — labeled with its proper name, its aliases, when to reach for it, and the CSS/JS idea that makes it work. Learn the vocabulary; build better sites.

    This page eats its own cooking. Patterns used by the site itself:
    • Sticky header that hides on scroll-down, returns on scroll-up
    • Sidebar layout with a sticky table of contents
    • Scrollspy — the TOC highlights the section in view
    • Off-canvas drawer for the nav on small screens (resize to see it)
    • Skip link — press Tab once at the top of the page
    • Dark mode via design tokens + prefers-color-scheme, saved to localStorage
    • Fluid type scale with clamp() — resize the window
    • Live filter — the search box in the sidebar
    • Back-to-top button that appears after scrolling
    • Reduced-motion respect via prefers-reduced-motion
    • Progressive disclosure — the "How it's built" toggles
    • Card frame around every specimen, on a surface/background token pair

    01

    Layout

    How the big boxes get arranged. Most modern layout is a handful of named CSS Grid and Flexbox recipes.

    Holy Grail Layout

    three-column layout, header–nav–main–aside–footer

    Layout

    The classic page skeleton: full-width header and footer, with a fluid main column flanked by two fixed-width columns. Historically painful; now trivial with named grid areas. Collapses to a single column on small screens.

    header
    nav
    main
    aside
    footer

    Use when: documentation, dashboards, news sites — anything with persistent side navigation plus supplementary content.

    How it's built
    .holy {
  display: grid;
  grid-template-columns: 120px 1fr 120px;
  grid-template-areas:
    "header header header"
    "nav    main   aside"
    "footer footer footer";
}
.holy__m { grid-area: main; }
/* mobile: one column, areas stacked */

    The Sidebar

    Every Layout "Sidebar", intrinsic sidebar

    Layout

    Two columns where one has a fixed preferred width and the other takes the rest — but when there isn't room, they wrap into a stack. No media query needed; the layout responds to its own container. Shrink the window to see it wrap.

    sidebar
    (flex-basis: 12rem)
    main (flex-grow: 999; min-width: 55%)

    Use when: a media object, a settings panel next to a preview, any "label + content" pair that should degrade gracefully.

    How it's built
    .sb { display: flex; flex-wrap: wrap; gap: .75rem; }
.sb > :first-child { flex-basis: 12rem; flex-grow: 1; }
.sb > :last-child  { flex-basis: 0; flex-grow: 999; min-inline-size: 55%; }

    Responsive Card Grid

    RAM (repeat, auto-fit, minmax), auto-fill grid

    Layout

    One line of CSS that fits as many equal columns as will hold a minimum width, and reflows without breakpoints. The single most useful grid recipe.

    1
    2
    3
    4
    5
    6

    Use when: product grids, blog listings, team pages, galleries.

    How it's built
    .ram {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(140px, 100%), 1fr));
  gap: .75rem;
}
/* auto-fit collapses empty tracks; auto-fill keeps them */

    Bento Grid

    bento box, mosaic grid, feature grid

    Layout

    A tiled grid where cells span different numbers of rows and columns, like compartments in a Japanese lunch box. Popularized by Apple marketing pages. Uses grid-column: span n.

    2×2
    2×1
    1×2
    1×1
    3×1

    Use when: feature overviews, dashboards, portfolio landing pages — content of varying importance you want to show at once.

    How it's built
    .bento { display: grid; grid-template-columns: repeat(4, 1fr); grid-auto-rows: 70px; gap: .6rem; }
.b1 { grid-column: span 2; grid-row: span 2; }
.b5 { grid-column: span 3; }

    Split Screen

    50/50 layout, media + text hero

    Layout

    Two equal halves — usually image on one side, copy on the other. Stacks vertically on narrow screens. Often alternated ("zig-zag") down a marketing page.

    Visual half

    image, illustration, product shot

    Text half

    Headline, supporting copy, a call to action.

    Use when: heroes, feature explainers, login pages (form on one side, brand on the other).

    How it's built
    .split { display: grid; grid-template-columns: repeat(auto-fit, minmax(240px, 1fr)); }

    Full-Bleed Section

    breakout, edge-to-edge, "bleed"

    Layout

    Text sits in a comfortable narrow measure, but a specific element (image, colored band) breaks out to the container's edges. Borrowed from print, where "bleed" means ink runs off the page.

    Constrained prose column, easy to read…

    full-bleed band

    …and back to the constrained column.

    Use when: long-form articles with hero images, colored CTA bands inside a narrow content column.

    How it's built
    .wrap > * { max-width: 65ch; margin-inline: auto; }
.wrap > .full-bleed { max-width: none; margin-inline: calc(-1 * var(--pad)); }
/* or with grid: grid-template-columns: 1fr min(65ch, 100%) 1fr; .full-bleed { grid-column: 1 / -1; } */

    The Stack

    flow utility, lobotomized owl (* + *)

    Layout

    Puts consistent vertical space between siblings, never above the first or below the last. Uses the "owl" selector * + * which matches any element that follows a sibling.

    one
    two
    three

    Use when: everywhere. It replaces ad-hoc margin-bottom on every element and is the basis of good "vertical rhythm".

    How it's built
    .stack > * + * { margin-block-start: var(--stack-space, 1rem); }

    The Cluster

    inline group, tag cloud, wrapping row

    Layout

    A row of items of unknown width that wrap naturally with even spacing in both directions. gap makes this trivial.

    designcsslayoutaccessibilitytypographymotioncolor theorygrid

    Use when: tags, filter chips, button groups, nav links.

    How it's built
    .cluster { display: flex; flex-wrap: wrap; gap: .5rem; align-items: center; }

    The Center

    place-items center, absolute centering

    Layout

    Perfect horizontal + vertical centering, once the hardest thing in CSS. Now: display: grid; place-items: center.

    centered

    Use when: empty states, hero content, modals, icons in buttons.

    How it's built
    .center { display: grid; place-items: center; }

    The Cover / Hero

    above-the-fold hero, cover block, jumbotron

    Layout

    A block that fills the viewport height with a centered principal element and optional header/footer pinned to top and bottom. The "hero" is the first thing users see — the space above the fold.

    ↑ pinned top (nav)

    Centered headline

    Supporting line + primary CTA

    ↓ pinned bottom (scroll cue)

    Use when: landing pages, section intros.

    How it's built
    .cover { min-height: 100vh; display: grid; grid-template-rows: auto 1fr auto; }
.cover > :nth-child(2) { align-self: center; }

    Sticky Footer

    bottom-pinned footer

    Layout

    The footer stays at the bottom of the viewport when content is short, but is pushed down naturally when content is long. Not to be confused with position: sticky.

    header
    short content (1fr)
    footer stays at bottom

    Use when: every page — a footer floating mid-screen looks broken.

    How it's built
    body { min-height: 100vh; display: grid; grid-template-rows: auto 1fr auto; }

    Aspect Ratio Boxes

    padding-top hack (legacy), ratio containers

    Layout

    Boxes that keep a fixed proportion as they resize — essential for image/video placeholders so the layout doesn't jump when media loads (avoids "layout shift").

    1:1
    4:3
    16:9
    2:3

    Use when: thumbnails, video embeds, avatars, cards with media.

    How it's built
    .thumb { aspect-ratio: 16 / 9; object-fit: cover; }

    Container Queries

    component-level responsiveness, element queries

    Layout

    Media queries respond to the viewport; container queries respond to the parent's width. The same card can be a vertical stack in a narrow sidebar and horizontal in a wide main column. Drag the corner handle to resize this box.

    Card title

    Goes horizontal past 420px of container width.

    ↘ drag the bottom-right corner

    Use when: reusable components dropped into layouts of unknown width.

    How it's built
    .host { container-type: inline-size; }
@container (min-width: 420px) { .card { grid-template-columns: 160px 1fr; } }

    Navigation

    How people find their way. Good nav answers "where am I, where can I go, how do I get back?"

    Navbar

    top nav, app bar, header bar

    Navigation

    Brand on the left, links in the middle or right, one primary call-to-action highlighted. The site's own header (above) is a sticky navbar that hides on scroll-down — a pattern that reclaims screen space on mobile.

    BrandProductPricingDocsSign in

    Use when: always. Keep it to 5–7 items; more than that wants a mega menu or a drawer.

    How it's built
    .nav { display: flex; align-items: center; gap: 1rem; }
.nav .spacer { flex: 1; }   /* pushes the rest right */
/* sticky + hide-on-scroll: position: sticky; top: 0; toggle .is-hidden via scroll direction in JS */

    Hamburger → Off-Canvas Drawer

    side drawer, slide-out menu, mobile nav

    Navigation

    The ☰ icon opens a panel that slides in from the edge over a dimmed backdrop ("scrim"). Tap the scrim or press Esc to close. This site uses one under 900px wide — try it, or click below.

    On wide screens the sidebar is already visible, so this only slides in on narrow viewports.

    Use when: mobile nav, filter panels, settings. Avoid hiding primary nav behind a hamburger on desktop — discoverability drops.

    How it's built
    .drawer { position: fixed; inset: 0 auto 0 0; transform: translateX(-100%); transition: transform .4s; }
body.drawer-open .drawer { transform: none; }
.scrim { position: fixed; inset: 0; background: rgb(0 0 0 / .4); }

    Mega Menu

    flyout panel, multi-column dropdown

    Navigation

    A large dropdown panel showing many links grouped in columns — used when a site has too many sections for a plain dropdown. Hover or click "Products".

    Brand
    Build
    EditorComponentsTemplates
    Ship
    HostingDomainsAnalytics
    Learn
    DocsGuidesCommunity
    Pricing

    Use when: e-commerce, large corporate sites. Group by task, keep 3–5 columns.

    How it's built
    .mega { position: relative; }
.mega__panel { position: absolute; top: 100%; display: grid; grid-template-columns: repeat(3, 1fr); }
/* toggle [hidden] on click; aria-expanded on the trigger */

    Dropdown Menu

    action menu, context menu, kebab/overflow menu

    Navigation

    A button that reveals a short list of actions. The "kebab" (⋮) and "meatball" (⋯) icons are conventional triggers for overflow menus. Closes on outside click and Esc; arrow keys move focus.

    Use when: secondary actions on a row/card, user account menus.

    How it's built
    <button aria-haspopup="menu" aria-expanded="false" aria-controls="menu">
<ul role="menu" hidden><li role="none"><button role="menuitem">
/* JS: toggle hidden; document click outside → close; Escape → close & refocus trigger */

    Breadcrumbs

    breadcrumb trail, path navigation

    Navigation

    Shows where the current page sits in the hierarchy and lets users jump up levels. The current page is plain text (not a link) with aria-current="page".

    1. Home
    2. Library
    3. Patterns
    4. Breadcrumbs

    Use when: deep hierarchies — docs, e-commerce categories, file browsers. Not for flat sites.

    How it's built
    .crumbs { display: flex; gap: .4rem; list-style: none; }
.crumbs li + li::before { content: "/"; color: var(--muted); }

    Tabs

    tab bar, segmented views

    Navigation

    Switch between sibling panels in the same space. Only one visible at a time. Proper ARIA: role=tablist/tab/tabpanel, arrow keys move between tabs.

    Overview panel. Tabs are for peer content, not sequential steps — for steps use a stepper.
    Specs panel. Try ← → arrow keys while a tab is focused.
    Reviews panel. Underline indicator = the "selected" affordance.

    Use when: 2–6 related views of one object (product details, settings groups).

    How it's built
    [role=tab][aria-selected=true] { border-bottom: 2px solid var(--accent); }
[role=tabpanel][hidden] { display: none; }
/* JS: on click/arrow → set aria-selected, hidden, and roving tabindex */

    Pagination

    pager, page numbers

    Navigation

    Numbered links through a long list, with truncation ("…") for many pages. Alternatives: infinite scroll (auto-loads more) and load-more button. Pagination is best when users need to return to a specific spot.

    • ‹
    • 1
    • 2
    • 3
    • …
    • 12
    • ›

    Use when: search results, tables, archives.

    How it's built
    .pager [aria-current] { background: var(--accent); color: var(--accent-ink); }

    Stepper / Wizard

    progress steps, multi-step form indicator

    Navigation

    Shows position in a sequential flow: done, current, upcoming. Unlike tabs, order matters and later steps are often locked.

    1. ✓Cart
    2. 2Shipping
    3. 3Payment
    4. 4Review

    Use when: checkout, onboarding, any form too long for one screen.

    How it's built
    .stepper li + li::before { content: ""; width: 32px; height: 2px; background: var(--border); }
.is-done .dot { background: var(--success); }  .is-current .dot { border-color: var(--accent); }

    Table of Contents + Scrollspy

    on-this-page nav, anchor nav, active-section highlighting

    Navigation

    A list of in-page anchor links whose active item tracks the section currently in view. Look at the sidebar of this page as you scroll — that's it. Built with IntersectionObserver, not scroll listeners.

    ← The sidebar TOC on this page is the live demo. Also note scroll-margin-top on sections so anchors land below the sticky header, and scroll-behavior: smooth on html.

    Use when: long docs, articles with many headings, single-page sites.

    How it's built
    const io = new IntersectionObserver(entries => {
  entries.forEach(e => { if (e.isIntersecting) setActive(e.target.id); });
}, { rootMargin: "-20% 0px -70% 0px" });
sections.forEach(s => io.observe(s));

    Back-to-Top Button

    scroll-to-top, FAB (floating action button)

    Navigation

    A floating button that fades in after the user has scrolled a screen or so, and scrolls smoothly back to the top. A "FAB" more generally is any floating circular action button (Material Design term).

    ↘ Look at the bottom-right corner of this page — you've scrolled far enough for it to be visible.

    Use when: long pages, especially on mobile.

    How it's built
    window.addEventListener("scroll", () => btn.classList.toggle("is-visible", scrollY > 600), { passive: true });
btn.onclick = () => scrollTo({ top: 0, behavior: "smooth" });

    Skip Link

    skip-to-content, bypass block

    Navigation

    A visually hidden link, first in the tab order, that jumps keyboard users past the header straight to main content. Click somewhere blank on the page, then press Tab once — it appears top-left.

    Press Tab from the top of this page to reveal it.

    Use when: always. It's a WCAG requirement and costs three lines.

    How it's built
    .skip-link { position: absolute; top: -100px; }
.skip-link:focus { top: .5rem; }

    03

    Typography

    Ninety-five percent of web design is typography. These are the levers.

    Type Scale

    modular scale, typographic scale

    Typography

    A small set of font sizes derived from one ratio (e.g. 1.25 "major third", 1.333 "perfect fourth") instead of arbitrary numbers. Consistency comes from choosing sizes from the scale, never inventing new ones.

    Display--fs-4

    Heading--fs-3

    Subheading--fs-2

    Lead--fs-1

    Body--fs-0

    Caption--fs--1

    Use when: always — define 5–7 steps as tokens and use only those.

    How it's built
    /* ratio 1.25 from 1rem: 0.8, 1, 1.25, 1.563, 1.953, 2.441 … */
--fs-0: 1rem; --fs-1: 1.25rem; --fs-2: 1.563rem; --fs-3: 1.953rem;

    Fluid Type

    responsive typography, clamp() type

    Typography

    Font sizes that scale smoothly with the viewport between a minimum and maximum, without breakpoints. Every size on this page is fluid — resize the window and watch the headings.

    clamp(1.2rem, .5rem + 3vw, 2.6rem)

    min · preferred (scales with vw) · max

    Use when: headings and display type; body text can stay closer to fixed.

    How it's built
    h1 { font-size: clamp(2rem, 1.2rem + 3.5vw, 4rem); }
/* always include a rem term so it still responds to user zoom */

    Measure (Line Length)

    optimal line length, 45–75 characters, ch unit

    Typography

    Lines longer than ~75 characters are tiring: the eye loses its place on the return sweep. Constrain prose with max-width in ch units (width of the "0" glyph). Compare:

    ~65ch (good): The quick brown fox jumps over the lazy dog while the five boxing wizards jump quickly and the sphinx of black quartz judges my vow, packing my box with five dozen liquor jugs.

    Unconstrained (bad on wide screens): The quick brown fox jumps over the lazy dog while the five boxing wizards jump quickly and the sphinx of black quartz judges my vow, packing my box with five dozen liquor jugs, and then keeps going, and going, and the line gets very hard to follow back to the start.

    Use when: any paragraph text. 45–75ch; ~65ch is a good default.

    How it's built
    .prose { max-width: 65ch; }

    Visual Hierarchy

    typographic hierarchy, kicker/eyebrow + headline + dek

    Typography

    Size, weight, color, and spacing tell the eye what to read first. The three-level combo below is the workhorse: a small uppercase kicker (aka eyebrow/overline), a bold headline, and a muted dek (subhead), plus dim meta.

    Kicker / eyebrowThe headline carries the weightThe dek or subhead explains, in a lighter color and normal weight.Meta · 4 min read · Aug 2026

    Use when: section intros, cards, article headers, hero blocks.

    How it's built
    .kicker { font-size: .8rem; text-transform: uppercase; letter-spacing: .1em; color: var(--accent); font-weight: 700; }
.h { font-size: 1.6rem; font-weight: 700; line-height: 1.15; }
.sub { color: var(--muted); }

    Leading & Vertical Rhythm

    line-height, baseline grid

    Typography

    "Leading" (rhymes with sledding) is line spacing. Body text wants ~1.5–1.7; headings tighter (~1.1–1.2). Vertical rhythm means margins between blocks are multiples of one base unit, so the page feels evenly paced.

    Tight heading leading (1.15)

    Body leading around 1.6 lets the eye track lines comfortably. Spacing between paragraphs equals one line of text — that's rhythm.

    Headings get less space below than above so they visually attach to what follows (proximity).

    Use when: always. It's the difference between "off" and "polished" that nobody can name.

    How it's built
    body { line-height: 1.6; }  h1,h2,h3 { line-height: 1.15; }
p { margin: 0 0 1em; }  h2 { margin: 2em 0 .5em; }  /* more above, less below */

    Drop Cap

    initial letter, versal

    Typography

    An enlarged first letter that drops into the paragraph. Editorial flourish signalling "long-form starts here."

    Once upon a time, before flexbox and grid, developers floated everything and cleared their fixes with a prayer. The drop cap is one float that still earns its keep.

    Use when: essays, magazine-style articles. Once per piece, never in UI.

    How it's built
    p::first-letter { float: left; font-size: 3.4em; line-height: .85; padding-right: .12em; }
/* modern: initial-letter: 3; (Safari/Chrome) */

    Pull Quote

    callout quote, lift-out

    Typography

    A striking line repeated from the article at larger size to break up long text and lure skimmers. Different from a blockquote, which introduces new quoted material.

    "Good typography is invisible; bad typography is everywhere."
    — an oft-repeated maxim

    Use when: long articles, testimonials, case studies.

    How it's built
    .pullquote { font-family: serif; font-size: 1.6rem; border-block: 2px solid var(--accent); padding: 1rem 0; text-wrap: balance; }

    Text Truncation

    ellipsis, line clamp

    Typography

    Cutting text with "…" — single-line via text-overflow, multi-line via -webkit-line-clamp. Always give a way to see the full text (title attribute, expand, or detail page).

    Single-line truncation keeps table cells and card titles tidy and prevents overflow

    Multi-line clamp cuts after N lines. This paragraph is intentionally long so that it overflows the two-line limit and gets an ellipsis at the end of the second line, demonstrating the effect.

    Use when: cards, tables, previews with fixed heights.

    How it's built
    .truncate { white-space: nowrap; overflow: hidden; text-overflow: ellipsis; }
.clamp { display: -webkit-box; -webkit-line-clamp: 2; -webkit-box-orient: vertical; overflow: hidden; }

    Typographic Details

    tabular numbers, text-wrap: balance, small caps

    Typography

    Small settings that separate careful from careless: tabular numerals so digits align in columns; text-wrap: balance so headings don't leave one lonely word (an "orphan"); letter-spacing for uppercase.

    proportional (misaligned)

    1,111.11
    8,888.88
    4,040.40

    tabular-nums (aligned)

    1,111.11
    8,888.88
    4,040.40

    text-wrap: balance

    Balanced headings avoid a lonely last word

    Use when: tables/stats (tabular), all headings (balance), uppercase labels (letter-spacing .05–.12em).

    How it's built
    .tnum { font-variant-numeric: tabular-nums; }
h1, h2, h3 { text-wrap: balance; }   p { text-wrap: pretty; }
.label { text-transform: uppercase; letter-spacing: .08em; }

    04

    Feedback & Overlays

    How the interface talks back — telling users what happened, what's loading, and what needs a decision.

    Modal Dialog

    modal, lightbox, overlay dialog

    Feedback

    Blocks the page until dismissed. Native <dialog> gives you the backdrop, focus trapping, and Esc-to-close for free. Rule: modals interrupt, so use them only for decisions that must be made now.

    Delete 3 items?

    This can't be undone. Notice the dimmed backdrop, focus inside the dialog, and that Esc closes it.

    Use when: destructive confirmations, short focused forms. Not for content that could be a page.

    How it's built
    <dialog>…</dialog>   dialog.showModal();  dialog.close();
dialog::backdrop { background: rgb(0 0 0 / .45); }

    Toast / Snackbar

    notification, growl, flash message

    Feedback

    A brief, non-blocking message that appears at an edge and dismisses itself. A snackbar (Material term) is a toast with one optional action, like "Undo". Should live in an aria-live region so screen readers announce it.

    Use when: confirming background actions (saved, sent, copied). Not for errors that need attention.

    How it's built
    <div class="toast-region" aria-live="polite"></div>
/* JS: append .toast, setTimeout → add .is-leaving → remove on animationend */

    Tooltip

    hint, infotip

    Feedback

    A tiny label on hover/focus that explains an element. Never put essential info only in a tooltip (no hover on touch). Show on focus too, for keyboard users.

    Hover or tab to this term or this one.

    Use when: icon-only buttons, abbreviations, tiny clarifications.

    How it's built
    .tip::after { content: attr(data-tip); position: absolute; bottom: 100%; opacity: 0; }
.tip:hover::after, .tip:focus-visible::after { opacity: 1; }

    Popover

    non-modal dialog, anchored panel, flyout

    Feedback

    Richer than a tooltip, lighter than a modal: an anchored panel with interactive content that closes on outside click ("light dismiss"). The native Popover API handles it with zero JS.

    Share this specimen

    Native [popover] — no JS. Click outside to dismiss.

    Use when: share menus, filter panels, date pickers, "more info" cards.

    How it's built
    <button popovertarget="p">Share</button>
<div popover id="p">…</div>   /* :popover-open, light dismiss, top layer — all built in */

    Accordion / Disclosure

    collapsible, expander, FAQ list

    Feedback

    A disclosure is one show/hide toggle; an accordion is a stack of them. Native <details>/<summary> works without JS; the name attribute makes them exclusive (open one, others close).

    What's the difference from tabs?
    Accordions stack vertically and can show several panels at once; tabs show one panel in a fixed area.
    Is it accessible?
    Native details/summary is keyboard-operable and announced correctly. Style the summary, hide the default marker.
    Can it animate?
    Yes — see "Animate Height" in the Motion section, or use interpolate-size: allow-keywords in new browsers.

    Use when: FAQs, settings groups, long forms — progressive disclosure of secondary detail.

    How it's built
    <details name="faq"><summary>Question</summary><div>Answer</div></details>
summary::after { content: "+"; }  details[open] summary::after { transform: rotate(45deg); }

    Skeleton Screen

    content placeholder, shimmer, ghost UI

    Feedback

    Grey shapes in the layout of the content that's coming, often with a shimmer sweep. Feels faster than a spinner because the page's structure is already visible.

    Use when: loading lists, cards, profiles — anything with predictable shape.

    How it's built
    .sk { background: linear-gradient(90deg, #eee 25%, #ddd 37%, #eee 63%); background-size: 400% 100%; animation: shimmer 1.4s infinite; }
@keyframes shimmer { from { background-position: 100% 0 } to { background-position: 0 0 } }

    Spinners & Progress

    loading indicator, activity indicator, determinate/indeterminate progress

    Feedback

    Determinate progress shows how much is done; indeterminate just says "working". A loading button swaps its label for a spinner and disables itself to prevent double-submits.

    determinate

    indeterminate

    Use when: spinner for <1–2s waits, skeleton for content, progress bar for uploads/multi-step jobs.

    How it's built
    .spinner { border: 3px solid #ddd; border-top-color: var(--accent); border-radius: 50%; animation: spin .8s linear infinite; }
.btn.is-loading { color: transparent; }  .btn.is-loading::after { /* spinner */ }

    Badges, Chips & Tags

      09

      Glossary

      Vocabulary that comes up in design reviews, tutorials, and hand-offs. Knowing the word is half of noticing the thing.

      Above the fold
      What's visible before scrolling. From newspapers folded on the stand.
      Affordance
      A visual cue that something can be interacted with — a button looks pressable, a link looks clickable.
      Atomic design
      Brad Frost's hierarchy: atoms (button) → molecules (search field) → organisms (header) → templates → pages.
      BEM
      Block__Element--Modifier CSS naming (.card__title--large). Used on this site.
      Breakpoint
      A viewport width where a media query changes the layout. Common: 640, 768, 1024, 1280.
      Call to action (CTA)
      The button/link you most want clicked. One primary CTA per screen.
      Chrome
      The UI framing around content: headers, sidebars, toolbars.
      Cognitive load
      How much thinking the interface demands. Reduce it: fewer choices, familiar patterns, clear hierarchy.
      Cumulative Layout Shift (CLS)
      Content jumping as things load. Prevent with aspect-ratio boxes, reserved space, font-display swap tuning.
      Dark pattern
      Design that tricks users (hidden unsubscribe, pre-checked upsells). Don't.
      Design system
      Tokens + components + guidelines, documented, so a team ships consistent UI.
      F-pattern / Z-pattern
      Eye-tracking shapes: text-heavy pages read in an F; sparse landing pages scan in a Z (logo → nav → hero → CTA).
      Fitts's law
      Bigger and closer targets are faster to hit. Make buttons big; put them where the pointer already is.
      Fold
      See "above the fold". Less meaningful now with varied screens; still a useful concept.
      Gestalt principles
      Proximity (close = related), similarity, continuity, closure, common region — how the eye groups things. Spacing is grouping.
      Grid (12-column)
      Classic layout system: 12 equal columns with gutters; elements span 3, 4, 6, etc.
      Hick's law
      More options → slower decisions. Trim menus.
      Hit target / tap target
      The tappable area. Minimum ~44×44px on touch.
      Interaction states
      default, hover, focus, active (pressed), disabled, loading, selected, visited.
      Jank
      Stuttery scrolling/animation from dropped frames. Animate only transform and opacity.
      Kerning / tracking / leading
      Space between letter pairs / across a word (letter-spacing) / between lines (line-height).
      Mobile-first
      Write base styles for small screens, then add complexity with min-width media queries.
      Modal vs non-modal
      Modal blocks the rest of the UI (dialog); non-modal doesn't (popover, toast).
      Negative space / whitespace
      Empty area. Not wasted — it's what creates grouping and calm.
      Optimistic UI
      Show the result immediately (liked, sent), then reconcile with the server; roll back on failure.
      Orphan / widow
      A single word alone on the last line (orphan) or a single line stranded at the top of a column (widow). text-wrap: balance/pretty helps.
      Progressive disclosure
      Show the basics; reveal detail on demand (accordions, "advanced" toggles).
      Progressive enhancement
      Works with HTML alone, better with CSS, best with JS. Opposite of graceful degradation's direction, same goal.
      Responsive vs adaptive
      Responsive: fluid layout that reflows continuously. Adaptive: fixed layouts swapped at breakpoints.
      Semantic HTML
      Using the element that means the thing: nav, main, article, button, dialog. Free accessibility and SEO.
      Skeuomorphism / flat design
      Mimicking real materials (leather, stitching) vs. abstract flat shapes. Flat won ~2013; "flat 2.0" added subtle depth back.
      Surface
      A raised container color (card, sheet) distinct from the page background. Tokens: --bg vs --surface.
      Utility classes
      Single-purpose classes like .mt-4, .flex (Tailwind style). Fast; can bloat markup.
      Viewport units
      vw, vh, dvh, svh, lvh — % of the viewport. Use dvh for mobile-safe full height.
      Visual weight
      How much an element pulls the eye: size, contrast, color saturation, density. Balance it.
      WCAG
      Web Content Accessibility Guidelines. Levels A / AA / AAA. Aim for AA.
      Wireframe → mockup → prototype
      Boxes-and-lines structure → styled static picture → clickable simulation.
