    A field guide

    Web design, one specimen at a time.

    Every entry below is a real, working example of a layout, component, interaction, or visual style — labeled with its proper name, its aliases, when to reach for it, and the CSS/JS idea that makes it work. Learn the vocabulary; build better sites.

    This page eats its own cooking. Patterns used by the site itself:
    • Sticky header that hides on scroll-down, returns on scroll-up
    • Sidebar layout with a sticky table of contents
    • Scrollspy — the TOC highlights the section in view
    • Off-canvas drawer for the nav on small screens (resize to see it)
    • Skip link — press Tab once at the top of the page
    • Dark mode via design tokens + prefers-color-scheme, saved to localStorage
    • Fluid type scale with clamp() — resize the window
    • Live filter — the search box in the sidebar
    • Back-to-top button that appears after scrolling
    • Reduced-motion respect via prefers-reduced-motion
    • Card frame around every specimen, on a surface/background token pair

    Bento Grid

    bento box, mosaic grid, feature grid

    Layout

    A tiled grid where cells span different numbers of rows and columns, like compartments in a Japanese lunch box. Popularized by Apple marketing pages. Uses grid-column: span n. Click any tile to cycle its span and re-compose the box.

    Use when: feature overviews, dashboards, portfolio landing pages — content of varying importance you want to show at once.

    Full-Bleed Section

    breakout, edge-to-edge, "bleed"

    Layout

    Text sits in a comfortable narrow measure, but a specific element (image, colored band) breaks out to the container's edges — via negative inline margins, or a three-column grid where the bleed spans all columns. Borrowed from print, where "bleed" means ink runs off the page.

    02

    Page Archetypes

    How whole pages are composed, by industry. Each wireframe below is scrollable — the bands are in the order real sites in that vertical use, labeled with the job each band does. Composition, not style: any of these can be executed brutalist or corporate. Agency sites are the portfolio archetype plus a services band and a client-logo strip; medical & dental take the trades skeleton and swap the quote form for a booking widget plus an insurance band; fitness adds a live class schedule and transparent pricing to the same trust frame. Learn these seven and you can compose the rest.

    Restaurant & Hospitality

    photography-led, menu-first, logistics above the fold

    Archetype

    Most visitors arrive with one question — can I eat there tonight? — so hours, location, and phone live at the top, not the footer, and the menu is a first-class object: real HTML with prices and dietary flags, never a PDF download. Photography carries the atmosphere; the story section sits low because it answers no transactional question. Reservations and ordering are usually embedded third-party widgets.

    Headername · hours · phone · Reserve button — sticky
    Herofull-bleed food/interior photography + cuisine one-liner + hours & address repeated
    Reserve / Orderthe one dominant action — booking widget or online ordering
    MenuHTML, categorized, priced, allergen-flagged — the real product page
    Gallerydishes and room — appetite + setting expectations
    Storychef, sourcing, history — differentiation, so it sits low
    Find usmap embed · address · hours again · phone — the most-visited band on mobile

    Primary conversion: reserve a table (dine-in) or order online (fast-casual), repeated in header, hero, and after the menu. Classic mistake: burying hours, location, and the menu under a decorative hero and brand copy — or shipping the menu as a PDF.

    Local Service & Trades

    plumbing / HVAC / roofing / construction — the call-first page

    Archetype

    The most conversion-driven archetype and the least written about. It runs two intents at once: an emergency path (burst pipe at 2am — tap-to-call, high contrast, 24/7 language) and a planned-work path (new roof — quote form, financing, reviews). The phone number is the product: in the top strip, the header, the hero, and a sticky bar on mobile, so a caller never has to scroll to find it. Trust is front-loaded — license number, insured, years in business, review stars — with real crew-and-truck photos, not stock. Per-city service-area pages are a first-class section, driven by local search.

    ☎ 24/7 emergencytap-to-call strip — the highest-converting element
    Headerlogo · 4–5 links max · big clickable phone number
    Hero"AC Repair in Mesa, AZ" + ★ 4.9 reviews + Licensed & Insured + two CTAs: Call now / Free quote
    Trust rowlicense № · insured · BBB · manufacturer certs · guarantees
    Services3–6 cards (repair / replace / maintain), each its own page
    Reviewsembedded Google reviews with names and dates
    Before / aftermatched-angle project gallery — the trades' portfolio
    Service areacity + neighborhood list, map — feeds per-city pages
    Financingprominent for big-ticket work (roof, HVAC install)
    Quote form4 fields max: name, phone, zip, issue
    Footername/address/phone exactly matching the Google Business Profile
    ☎ Call nowsticky on mobile — visible at every scroll position

    Primary conversion: the phone call — repeated at every viewport; the quote form is the secondary path for planned work. Classic mistake: a phone number that isn't visible and tappable at all times on mobile (footer-only, or not a tel: link), compounded by slow mobile load and long forms.

    Creative Portfolio

    work-first, chrome-last

    Archetype

    Navigation and copy are minimized so the work lands within one scroll: a name-plus-positioning line in oversized type, then straight into a curated grid of three to six projects. The real signature of the vertical is the case study anatomy: context and problem → my role, stated early → only the process steps that show decision-making → outcome, with numbers if they exist. Three to five deep case studies beat twenty shallow ones. The contact action stays deliberately quiet — the page's job is getting a case study read.

    Heroname + one-line positioning in display type — "Product designer in Berlin, previously X"
    Selected work3–6 curated projects: title, category, hover preview — the body of the page
    Case studyproblem → my role → decisive process moments → outcome
    Archivequiet "all work" link — depth without clutter
    Bioone paragraph, photo optional
    Contactplain-text email + availability status — quiet, not shouty

    Primary conversion: the email / "available for work" contact — mentioned in the hero, end of each case study, and footer, never repeated aggressively. Classic mistake: case studies that document every process step instead of the decisions — recruiters skim; a vague "the goal was to improve the UX" with no stated outcome loses them.

    SaaS / Product Landing

    the argument in a fixed order

    Archetype

    The page is an argument, and the band order is the argument's logic — each section answers the next objection: what is it → who else uses it → what problem it kills → how it works → what it costs. Reordering it (features before problem, pricing before proof) breaks the argument. One conversion action rules the page; trial and demo as co-equal buttons dilute each other. The current shift: static hero screenshots giving way to embedded interactive product demos.

    Headerlogo · product · pricing · docs · the same primary CTA — sticky
    Heroone claim, under ~8 words, outcome not jargon + interactive demo or product video
    Primary CTAstart free trial or book a demo — never both as equals
    Logo strip"who else uses this" — answered before any feature claim
    Problem → benefitname the pain before the solution
    Featuresbento grid for complex products, alternating bands for simple ones
    How it works3 steps — shrink the perceived effort
    Customer evidencenamed testimonials, case-study numbers, video
    Pricingtransparent tiers, one highlighted — transparency is itself a trust signal
    FAQobjection handling (and structured-data SEO)
    Final CTArestate the claim + the same action; nothing after but the footer

    Primary conversion: one action — trial or demo — in the header, hero, after evidence, on every pricing card, and in the closing band. Classic mistake: a vague, jargon-heavy hero plus competing CTAs; the visitor's "what do I get?" test fails in the first five seconds and no lower band matters.

    E-commerce — Listing vs Product

    PLP + PDP + cart drawer

    Archetype

    Two distinct pages doing two distinct jobs. The listing page is a filtering machine: facets combine as OR within a group and AND across groups, every filter value shows a live product count so no path dead-ends, and the default sort is "bestselling". The product page is an anxiety-reduction machine: gallery beside a buy-box, the trust row (shipping, returns, payment marks — three or four badges, more reads as desperate) directly under the add-to-cart button, reviews below. Adding to cart opens a drawer, not a new page — with a free-shipping progress bar at the top. On long mobile pages a sticky add-to-cart bar follows the reader down.

    Filtersfacets with live counts; bottom-sheet on mobile
    Applied chipsremovable, one per active filter
    Sortdefault: bestselling
    Product gridimage · name · price · rating count · swatches
    Load moreor pagination — keep a way back to a spot
    Product (PDP)
    Gallery + buy boxmulti-angle zoomable images · title · ★ rating link · price · variant swatches
    Add to cartthe dominant button — opens the cart drawer
    Trust rowfree shipping · returns · payment marks — right under the button
    Detailsaccordion: description bullets, specs, shipping/returns
    Reviewsmost shoppers read them before buying
    Cross-sell"pairs well with" recommendations
    Sticky add-to-cartappears when the buy box scrolls away

    Primary conversion: add to cart → checkout, restated by the sticky bar and the drawer's checkout button. Classic mistake: filter dead ends on the listing page (no counts, alphabetical facet dumps) and, on the product page, weak imagery with the buy action buried below the fold on mobile.

    Real Estate

    search-first — the hero is a tool

    Archetype

    The only archetype whose hero is a working widget: an IDX/MLS property search (location, price, beds) over a full-bleed photo, often with a map-search entry point. Everything else supports the two lead funnels — buyers inquiring about listings, and sellers lured by a "what's my home worth?" valuation form.

    Search heroIDX search bar: location · price · beds — a functional tool, not a picture
    Featured listingsphoto · price · beds/baths · "view details" cards
    Seller funnel"What's my home worth?" — the valuation lead magnet
    Agent / teamcredibility: sales record, local tenure, photo
    Neighborhood guidesarea pages — local SEO and buyer research
    Testimonialsnamed buyers and sellers
    Footerbrokerage, licensing, contact

    Primary conversion: property inquiries plus home-valuation lead capture — two funnels, one page. Classic mistake: hiding the search behind marketing copy; the visitor came to search, and a hero that's just a mood photo sends them to a portal instead.

    Legal

    practice areas + results + bios

    Archetype

    Two bands carry weight no other vertical gives them: case results (anonymized, concrete outcomes — often dollar figures in personal injury) and attorney bios, which are the most-visited pages on a firm's site — people hire a lawyer, not a firm. Practice-area cards each link to a deep page; that structure is the site's search backbone. A large share of mobile visitors call straight from the homepage, so the phone sits above the fold beside a "free consultation" offer.

    Herocase-type headline ("Injured? …") + clickable phone + free-consultation CTA
    Practice areasgrid of cards, each a deep page — the SEO backbone
    Case resultsconcrete, anonymized outcomes — "$2.1M settlement"
    Attorney biosreal photography, narrative voice — the most-visited pages
    Awards & testimonialsSuper Lawyers, Avvo, client quotes
    Free consultationshort form + phone repeated

    Primary conversion: the call or the free-consultation form. Classic mistake: generic gavel-and-columns stock imagery and buried bios — the two things visitors actually came to judge (who are you, what have you won) pushed below interchangeable marketing copy.

    Ninety-five percent of web design is typography. These are the levers.

    Type Scale

    modular scale, typographic scale

    Typography

    A small set of font sizes derived from one ratio (e.g. 1.25 "major third", 1.333 "perfect fourth") instead of arbitrary numbers. Consistency comes from choosing sizes from the scale, never inventing new ones.

    Fluid Type

    responsive typography, clamp() type

    Typography

    Font sizes that scale smoothly with the viewport between a minimum and maximum, without breakpoints. Always include a rem term in the preferred value so text still grows when the user zooms. Every size on this page is fluid — resize the window and watch the headings.

    clamp(1.2rem, .5rem + 3vw, 2.6rem)

    min · preferred (scales with vw) · max

    Use when: headings and display type; body text can stay closer to fixed.

    Measure (Line Length)

    optimal line length, 45–75 characters, ch unit

    Typography

    Lines longer than ~75 characters are tiring: the eye loses its place on the return sweep. Constrain prose with max-width in ch units (width of the "0" glyph). Compare:

    Adjustable measure: The quick brown fox jumps over the lazy dog while the five boxing wizards jump quickly and the sphinx of black quartz judges my vow, packing my box with five dozen liquor jugs.

    Unconstrained (bad on wide screens): The quick brown fox jumps over the lazy dog while the five boxing wizards jump quickly and the sphinx of black quartz judges my vow, packing my box with five dozen liquor jugs, and then keeps going, and going, and the line gets very hard to follow back to the start.

    Use when: any paragraph text. 45–75ch; ~65ch is a good default.

    Leading & Vertical Rhythm

    line-height, baseline grid

    Typography

    "Leading" (rhymes with sledding) is line spacing. Body text wants ~1.5–1.7; headings tighter (~1.1–1.2). Vertical rhythm means margins between blocks are multiples of one base unit, so the page feels evenly paced.

    Tight heading leading (1.15)

    Body leading around 1.6 lets the eye track lines comfortably. Spacing between paragraphs equals one line of text — that's rhythm.

    Headings get less space below than above so they visually attach to what follows (proximity).

    Use when: always. It's the difference between "off" and "polished" that nobody can name.

    Drop Cap

    initial letter, versal

    Typography

    An enlarged first letter that drops into the paragraph. Editorial flourish signalling "long-form starts here."

    Once upon a time, before flexbox and grid, developers floated everything and cleared their fixes with a prayer. The drop cap is one float that still earns its keep.

    Use when: essays, magazine-style articles. Once per piece, never in UI.

    Pull Quote

    callout quote, lift-out

    Typography

    A striking line repeated from the article at larger size to break up long text and lure skimmers. Different from a blockquote, which introduces new quoted material.

    "Good typography is invisible; bad typography is everywhere."
    — an oft-repeated maxim

    ↘ narrow the box — text-wrap: balance keeps the lines even

    Use when: long articles, testimonials, case studies.

    Text Truncation

    ellipsis, line clamp

    Typography

    Cutting text with "…" — single-line via text-overflow, multi-line via -webkit-line-clamp. Always give a way to see the full text (title attribute, expand, or detail page).

    Single-line truncation keeps table cells and card titles tidy and prevents overflow

    Multi-line clamp cuts after N lines. This paragraph is intentionally long so that it overflows the line limit and gets an ellipsis at the end of the last allowed line, demonstrating the effect — keep dragging the slider and watch where the cut lands.

    Use when: cards, tables, previews with fixed heights.

    05

    Feedback & Overlays

    How the interface talks back — telling users what happened, what's loading, and what needs a decision.

    Modal Dialog

    modal, lightbox, overlay dialog

    Feedback

    Blocks the page until dismissed. Native <dialog> gives you the backdrop, focus trapping, and Esc-to-close for free. Rule: modals interrupt, so use them only for decisions that must be made now.

    Delete 3 items?

    This can't be undone. Notice the dimmed backdrop, focus inside the dialog, and that Esc closes it.

    Use when: destructive confirmations, short focused forms. Not for content that could be a page.

    Toast / Snackbar

    notification, growl, flash message

    Feedback

    A brief, non-blocking message that appears at an edge and dismisses itself. A snackbar (Material term) is a toast with one optional action, like "Undo". Should live in an aria-live region so screen readers announce it.

    Use when: confirming background actions (saved, sent, copied). Not for errors that need attention.

    Tooltip

    hint, infotip

    Feedback

    A tiny label on hover/focus that explains an element. Never put essential info only in a tooltip (no hover on touch). Show on focus too, for keyboard users.

    Hover or tab to this term or this one.

    Use when: icon-only buttons, abbreviations, tiny clarifications.

    Popover

    non-modal dialog, anchored panel, flyout

    Feedback

    Richer than a tooltip, lighter than a modal: an anchored panel with interactive content that closes on outside click ("light dismiss"). The native Popover API handles it with zero JS.

    Share this specimen

    Native [popover] — no JS. Click outside to dismiss.

    Use when: share menus, filter panels, date pickers, "more info" cards.

    Accordion / Disclosure

    collapsible, expander, FAQ list

    Feedback

    A disclosure is one show/hide toggle; an accordion is a stack of them. Native <details>/<summary> works without JS; the name attribute makes them exclusive (open one, others close).

    What's the difference from tabs?
    Accordions stack vertically and can show several panels at once; tabs show one panel in a fixed area.
    Is it accessible?
    Native details/summary is keyboard-operable and announced correctly. Style the summary, hide the default marker.
    Can it animate?
    Yes — see "Animate Height" in the Motion section, or use interpolate-size: allow-keywords in new browsers.

    Use when: FAQs, settings groups, long forms — progressive disclosure of secondary detail.

    Skeleton Screen

    content placeholder, shimmer, ghost UI

    Feedback

    Grey shapes in the layout of the content that's coming, often with a shimmer sweep. Feels faster than a spinner because the page's structure is already visible.

      Entrances & Exits

      How things appear and disappear. An entrance tells the user what just arrived and why; an exit gets out of the way. The craft is choosing the family, the duration, and the choreography — not adding more motion.

      The Entrance Families

      fade-in, rise (slide-up), scale-in, blur-in, wipe, clip reveal

      Entrances

      Six ways to arrive, side by side — click any tile to replay it alone. Each says something different: fade is neutral; rise reads as content settling into place; scale as something newly created; blur as focus arriving; wipe and clip as deliberately unveiling something that was already there. Entrances want 200–500ms and ease-out — fast start, gentle landing.

      Use when: anything appears. Pick one family per surface and stick to it — mixed entrances read as chaos.

      Staggered Text Reveal

      split-text animation, letter stagger, word cascade

      Entrances

      The headline is split into words or letters and each fragment rises in with a small delay (30–60ms). JS wraps each fragment in a span with an index; one CSS rule turns the index into a delay. Total time should stay under ~700ms — a headline is not a film title.

      Design is in the details

      Use when: hero headlines, section titles on marketing pages. Keep the real text in the DOM (aria-label on the container, aria-hidden spans) so screen readers hear a sentence, not letters.

      Trends

      Styles placed in time — what's gathering momentum, what's everywhere, what has already turned. The point isn't fashion-watching; it's judgment: knowing when a look is right, what it costs, and what it will say about the site in three years. Snapshot as of mid-2026; hold it loosely.

      The State of the Styles

      rising · peaking · turned

      Trends

      Every entry expands — each one names the problem the trend solves, where it breaks down, and what it costs. "Rising" means loud discourse and growing use, not a guarantee; at least one rising style (tactile/skeuomorphic revival) is talked about far more than it is shipped.

      ▲ Rising

      Tactile texture
      Solves: AI-era sameness — grain, warmth and press-depth read as human. Breaks: texture over low-contrast text; literal skeuomorphism reads 2010. Costs: restraint — and the honesty that critical buzz still outpaces shipped usage.
      Kinetic typography
      Solves: a hero without hero-image weight; personality from type alone. Breaks: the instant body copy moves; ignoring reduced-motion. Costs: variable-font licensing and motion discipline.
      Scroll-driven native CSS
      Solves: scroll-linked motion without JS scroll listeners — smoother and off the main thread. Breaks: browser support is still uneven (Firefox behind a flag mid-2026); must be progressive enhancement. Costs: almost nothing when layered on properly.
      Adaptive / generative UI
      Solves: one page serving many intents; returning visitors skip the pitch. Breaks: unpredictable layouts erode muscle memory; privacy cost is real. Costs: every personalized variant is another state to design and QA.

      ● Peaking

      Bento grids
      Solves: showing many unequal things at once with clear hierarchy. Breaks: thin content stretched into boxes; static bentos are starting to look like everyone else. Costs: real content for every cell. The evolution is interactive cells, not abandonment.
      Glass / translucency
      Solves: layered depth and context — you see what's behind the panel. Breaks: contrast over busy backgrounds; even Apple added an opacity toggle after legibility complaints. Costs: GPU time on low-end devices. Contested: "defining the era" vs "accent only" — both positions are live.
      Mesh / aurora gradients
      Solves: cheap atmosphere, no photography needed. Breaks: it became the background noise of SaaS — differentiation now needs motion or restraint. Costs: genericness more than performance.
      3D & WebGL scenes
      Solves: product showcases and award-tier immersion nothing else matches. Breaks: payload, battery, accessibility; useless for content-first sites. Costs: specialist build effort — which is why it peaks at the high end and only trickles down.
      Neo-brutalism
      Solves: instant personality; impossible to mistake for a template. Breaks: dense productivity UIs; the chaotic variant tests badly for task success. Costs: it splits — disciplined brutalism thrives, anti-design brutalism is already fading.

      ▼ Turned

      Heavy parallax
      Solved: 2013's hunger for cinematic scrolling. Turned because: motion sickness, jank, and content held hostage by choreography. Now: subtle single-layer depth, or native scroll-driven animation.
      Scroll-jacking
      Solved: forcing a narrative sequence. Turned because: it fights the user's own scroll — the one interaction they own. Now: scroll-driven CSS that follows the reader instead of driving them.
      Extreme minimalism
      Solved: 2018's clutter, and it photographed well in portfolios. Turned because: beige-on-white sameness became its own noise, then AI templates made it free. Now: warm minimalism — still reduced, but with character-rich type and texture.
      Neumorphism
      Solved: soft, calm, single-surface aesthetics. Turned because: contrast and affordance failures were structural, not fixable. Now: a niche survivor in instrument-style UIs (players, smart-home), and soft shadows used with borders and labels.
      Hero video backgrounds
      Solved: instant atmosphere. Turned because: they wreck load metrics and mobile data budgets for decoration. Now: big type, gradients, lightweight 3D.
      Auto-carousels & custom cursors
      Solved: stakeholder arguments (put everything in the hero). Turned because: slide two is where content goes to die, and cursor gimmicks tax usability. Now: curated static heroes; one thing said well.

      Use when: choosing a direction for a redesign — check which column your reference sites live in, and how close to "turned" the look you love is.

      How to Judge a Trend

      the three questions + honest disagreements

      Trends

      Before adopting any look, ask: 1. What problem does it solve for this site — or is it decoration? 2. Where does it break — and does that overlap with your users (motion sensitivity, old devices, screen readers)? 3. What does it cost — build time, performance budget, accessibility risk, and how soon it will date. A trend that survives all three questions isn't a trend for you anymore; it's a decision. Some questions the industry itself hasn't settled — disagreements below, left unresolved on purpose.

      "Flat design is dead" — is it?
      As an ideology, yes: nobody argues for pure flatness anymore. As a substrate, no: most shipped UI is still flat surfaces with subtle depth and motion layered on ("flat-plus"). Both headlines exist in 2026 sources because both are true at different altitudes.
      Is glass the defining look or an accent?
      One camp points at Apple pushing translucency across every OS; the other points at the accessibility backlash and Apple's own opacity concession. Safe reading: glass is a legitimate layer treatment, not a system-wide identity — the disagreement is about dosage.
      Bento: must-have or already tired?
      Usage data says it's near-standard for SaaS homepages; commentary increasingly calls static bentos samey. Both are right — the grid is now table stakes, and differentiation moved inside the cells (live data, interaction, motion).
      Does the tactile revival actually ship?
      It dominates 2026 trend writing, but at least one large telemetry set found skeuomorphic styles in a fraction of a percent of real projects. Discourse leads production by a year or more — which is exactly why "one thread among several" is the honest framing.

      Use when: a stakeholder says "make it look like [award-winning site]" — run the three questions out loud before you commit the budget.

      12

      Glossary

      Vocabulary that comes up in design reviews, tutorials, and hand-offs. Knowing the word is half of noticing the thing.

      Above the fold
      What's visible before scrolling. From newspapers folded on the stand.
      Affordance
      A visual cue that something can be interacted with — a button looks pressable, a link looks clickable.
      Atomic design
      Brad Frost's hierarchy: atoms (button) → molecules (search field) → organisms (header) → templates → pages.
      BEM
      Block__Element--Modifier CSS naming (.card__title--large). Used on this site.
      Breakpoint
      A viewport width where a media query changes the layout. Common: 640, 768, 1024, 1280.
      Call to action (CTA)
      The button/link you most want clicked. One primary CTA per screen.
      Chrome
      The UI framing around content: headers, sidebars, toolbars.
      Cognitive load
      How much thinking the interface demands. Reduce it: fewer choices, familiar patterns, clear hierarchy.
      Cumulative Layout Shift (CLS)
      Content jumping as things load. Prevent with aspect-ratio boxes, reserved space, font-display swap tuning.
      Dark pattern
      Design that tricks users (hidden unsubscribe, pre-checked upsells). Don't.
      Design system
      Tokens + components + guidelines, documented, so a team ships consistent UI.
      F-pattern / Z-pattern
      Eye-tracking shapes: text-heavy pages read in an F; sparse landing pages scan in a Z (logo → nav → hero → CTA).
      Fitts's law
      Bigger and closer targets are faster to hit. Make buttons big; put them where the pointer already is.
      Fold
      See "above the fold". Less meaningful now with varied screens; still a useful concept.
      Gestalt principles
      Proximity (close = related), similarity, continuity, closure, common region — how the eye groups things. Spacing is grouping.
      Grid (12-column)
      Classic layout system: 12 equal columns with gutters; elements span 3, 4, 6, etc.
      Hick's law
      More options → slower decisions. Trim menus.
      Hit target / tap target
      The tappable area. Minimum ~44×44px on touch.
      Interaction states
      default, hover, focus, active (pressed), disabled, loading, selected, visited.
      Jank
      Stuttery scrolling/animation from dropped frames. Animate only transform and opacity.
      Kerning / tracking / leading
      Space between letter pairs / across a word (letter-spacing) / between lines (line-height).
      Mobile-first
      Write base styles for small screens, then add complexity with min-width media queries.
      Modal vs non-modal
      Modal blocks the rest of the UI (dialog); non-modal doesn't (popover, toast).
      Negative space / whitespace
      Empty area. Not wasted — it's what creates grouping and calm.
      Optimistic UI
      Show the result immediately (liked, sent), then reconcile with the server; roll back on failure.
      Orphan / widow
      A single word alone on the last line (orphan) or a single line stranded at the top of a column (widow). text-wrap: balance/pretty helps.
      Progressive disclosure
      Show the basics; reveal detail on demand (accordions, "advanced" toggles).
      Progressive enhancement
      Works with HTML alone, better with CSS, best with JS. Opposite of graceful degradation's direction, same goal.
      Responsive vs adaptive
      Responsive: fluid layout that reflows continuously. Adaptive: fixed layouts swapped at breakpoints.
      Semantic HTML
      Using the element that means the thing: nav, main, article, button, dialog. Free accessibility and SEO.
      Skeuomorphism / flat design
      Mimicking real materials (leather, stitching) vs. abstract flat shapes. Flat won ~2013; "flat 2.0" added subtle depth back.
      Surface
      A raised container color (card, sheet) distinct from the page background. Tokens: --bg vs --surface.
      Utility classes
      Single-purpose classes like .mt-4, .flex (Tailwind style). Fast; can bloat markup.
      Viewport units
      vw, vh, dvh, svh, lvh — % of the viewport. Use dvh for mobile-safe full height.
      Visual weight
      How much an element pulls the eye: size, contrast, color saturation, density. Balance it.
      WCAG
      Web Content Accessibility Guidelines. Levels A / AA / AAA. Aim for AA.
      Wireframe → mockup → prototype
      Boxes-and-lines structure → styled static picture → clickable simulation.
